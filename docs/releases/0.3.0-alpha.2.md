This alpha fixes receiver update workers failing to start from Decky when its backend has no desktop-session environment.

- Protected workers now connect to the current user's verified session bus. Suspend protection remains required; an unavailable session produces a clear error before launching a firmware worker.
- Both frontends label unsupported models and manual downloads **Download firmware only**. Preparation explains when the selected firmware is already installed or a source-to-destination update is unsupported.
- Existing receiver installation authorizations are unchanged. Controller flashing over USB, 2.4 GHz, and Bluetooth remains unavailable. This release does not enable additional firmware writes.

To update Decky, install `8bitdo-deck.zip` using **Decky Settings → Developer → Install Plugin from ZIP File**. No terminal environment exports are needed. Enable Developer mode under General if the page is hidden. Installing a desktop or CLI update does not upgrade Decky.

Existing standalone CLI installations can run:

```sh
eightbitdo app-update-check --channel alpha
eightbitdo app-update-apply 0.3.0a2 --channel alpha --confirm
```

Desktop installations can select **Alpha** in App settings, check for updates, and confirm the new version. macOS and Windows firmware writes remain disabled pending hardware validation; their installers still lack OS publisher signatures.
